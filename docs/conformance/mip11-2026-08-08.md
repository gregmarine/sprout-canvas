
Notes on the numbers:

- **Pressure is already normalized** (`0..1`), so `pressureIsNormalized` is true and `maxPressure`
  is not used as a divisor. This is the ordinary Android contract; the 4095-vs-4096 raw-count
  problem is a vendor-pipeline issue and does not arise here.
- **`tilt` tops out at 1.571 = π/2**, confirming `AXIS_TILT` is radians-from-perpendicular as
  documented — which is why it is captured as `ALTITUDE` and not as vendor `TILT`.
- **`tiltUnitsKnown = false` and no `TILT` channel**, correctly: raw vendor `tiltX`/`tiltY` do not
  exist on the ordinary Android input path (PLAN.md §3.5).
- **`size` is absent**, so the engine does not claim the channel. Absent means the device did not
  report it, not that it was zero.

## Caveat on synthesized input

`adb shell input stylus` events come from a **virtual input device that declares no motion axes**.
Two consequences worth knowing before reading any automated result on this device:

1. Strokes drawn that way carry `TIMESTAMP` only — no pressure, tilt or orientation. That is
   correct: each stroke records what *its own* digitizer reported.
2. The fountain and brush pens therefore fall back to the **velocity** curve, and an `adb` swipe is
   fast, so they render thin. With the real pen they respond to pressure.

The engine's *capabilities* are unaffected — it refuses to retract a channel the hardware declares
on the strength of one stroke (see the regression test in the table above). That refusal exists
because this very run exposed the opposite behaviour.

## Findings from this run

Four bugs were found by putting the library on hardware, all of them fixed and all of them now
covered by a test. Recorded in full in PLAN.md §5.11.

1. **A dismissed overlay kept excluding.** A `GONE` view is never laid out, so watching each
   registered view's own layout misses it — the canvas kept a dead region where a popup used to be.
   Now the tracker watches the view *tree*.
2. **`INVISIBLE` does not reach a global layout listener either.** Measured here, on API 34: `GONE`
   fires it, `INVISIBLE` does not. Needed a second, cheap pre-draw visibility check.
3. **Capabilities were downgraded by a single stroke** from an axis-less device, permanently
   reporting `TIMESTAMP`-only on hardware with a pressure-sensitive pen.
4. **A refused stroke latched the pen-activity gate open** — returning false from `ACTION_DOWN`
   stops Android delivering the rest of the gesture, so the `ACTION_UP` that closes the gate never
   arrived.
